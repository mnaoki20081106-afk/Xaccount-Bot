## 構成

```
Xaccount-Bot（販売・決済・納品・管理画面）
  ├─ 自販機 / 商品 / 在庫（vending_stock）
  ├─ 仕入れ画面（仕入れ品・支払い/ウォレット・履歴）── 署名付きプロキシ ──┐
  └─ supply bridge（HMAC）                                                  │
       GET  catalog / product stock                                          │
       POST deliver（補充）                                                  │
       POST withdraw（報酬の払い出し）            ← 追加                     │
       POST order-hold（無在庫の確保分を注文に紐付け）← 追加                 │
                                                                             ▼
Discord-Shiire（仕入れ専用）
  ├─ 仕入れ先（テンプレート: hstora / custom_api / manual、資格情報は暗号化保存）
  ├─ 仕入れ品（仕入れ先＋条件＋補充先商品＋在庫しきい値＋予算）
  ├─ エンジン（毎分: 補充先の在庫を見て不足分だけ仕入れ → 補充）
  ├─ 無在庫 API（在庫確認 → 先に仕入れ → 届いたら Xaccount-Bot の注文に確保）
  ├─ 資金（ウォレット = コインごとの入金元。仕入れ先残高の補充）
  └─ フォロ爆 / 招待キャンペーン / 無料配布（据え置き。報酬は Xaccount-Bot の商品在庫から）
```

### 仕入れ先テンプレート（アダプタ）

共通インターフェース（後から追加しやすくするため、テンプレートはこれだけ実装すれば足りる）:

- `fields`: 画面に出す設定項目（API キー、URL など）。秘密値は暗号化して D1 に保存
- `quote(item, qty)`: 仕入れ可能数・単価（無在庫の事前確認、通常補充の予算判定に使用）
- `order(item, qty, idempotencyKey)`: 注文
- `poll(order)`: 注文状態と届いた商品（文字列）の取得
- `balance()`: 仕入れ先残高（ある場合）と入金先（コイン・アドレス）

| テンプレート | 内容 |
|---|---|
| HSTORA | 既存の HSTORA 実装（署名・カタログ・品質判定・注文・Webhook）をアダプタ化。条件 = 検索上位 / シャドバンなし / 商品 ID 指定、単価上限、品質条件 |
| カスタム API | 在庫確認・注文・結果取得の URL、認証方式（Bearer / 任意ヘッダー / なし）、レスポンス内の在庫数・単価・商品・注文 ID の場所（JSON パス）を設定 |
| 手動投入 | 自分で貼り付けた在庫を補充先へ流す（既存の supplier_pool） |

### 資金

- ウォレット = Discord-Shiire が管理する自前ウォレット（コインごと）。仕入れ先残高が足りないとき、そこから仕入れ先の入金アドレスへ送金して補充する
- 自前ウォレットの安全策（必須）:
  - 秘密鍵は CREDENTIALS_ENCRYPTION_KEY で暗号化して D1 に保存。作成・取り込み後は画面にもログにも二度と出さない
  - 送金先は「登録済みの仕入れ先入金アドレス」の許可リストのみ。新しい送金先は管理画面での承認が必要
  - 1回 / 1日の送金上限、緊急停止、すべての送金の記録（txid）
  - 署名はWorker内で行い、未確認の送金がある間は次の送金をしない
- 対応コイン: まず LTC。コインごとの「チェーンアダプタ」（アドレス生成・残高/UTXO取得・送金の組み立てと署名・ブロードキャスト）を追加すれば増やせる設計
- Binance Japan はウォレットへの入金元（任意）として残す
- 各仕入れ品: 資金配分（%）＋ 1回 / 1日の金額上限 ＋ 単価上限
- 既存の安全装置（緊急停止、価格急変ガード、レート鮮度、一括承認、資金ロック）は維持
- PayPay → LTC 変換はウォレット残高が不足したときのみ（自動ではしない設定を既定にする）

### 無在庫販売（手順 A）

1. 購入者が数量を決める。補充先の在庫が足りず、その商品に無在庫販売 ON の仕入れ品がある
2. Xaccount-Bot → Shiire: 不足数の見積り（`quote`）。仕入れられない・予算外なら「在庫切れ」と表示して終了（お金は受け取らない）
3. Shiire が自分の資金で注文。購入者には「確保中」と表示
4. 商品が届いたら Xaccount-Bot の注文に確保（他の購入者には売られない）→ 購入者に送金リンク入力を案内
5. 入金確認 → 通常と同じ DM 納品
6. 期限内に支払われない / 届くのが遅すぎて注文が切れた場合、届いた商品は補充先の通常在庫になる
